# QFixLean: Formalizing Fixed-Point Quantum Search in Lean

[中文](README-zh.md)

QFixLean is a project for the **Quantum Scientific Computing course at Shanghai Jiao Tong University (Fall 2026)**.

Fixed-point quantum search addresses the overshooting problem in ordinary Grover search. We chose this topic to deepen our understanding of quantum algorithms while exploring how Lean can make their assumptions and correctness guarantees explicit and machine-checkable.

Using **Lean 4 and Mathlib**, the code now covers the required quantum fundamentals, the core probability and resource guarantees of [Grover’s 2005 π/3 fixed-point search algorithm](https://arxiv.org/abs/quant-ph/0503205), and the explicit-phase correctness and bit-oracle query upper bound of [Yoder, Low, and Chuang’s 2014 fixed-point amplitude amplification algorithm](https://arxiv.org/abs/1409.3305). The scope and assumptions of these results are described below.

We hope to contribute reusable definitions and proofs for quantum scientific computing and the Lean formalization community, gradually developing a foundation for learning about and verifying quantum algorithms.

The project pins **Lean 4.35.0** and **Mathlib v4.35.0**. With [elan](https://github.com/leanprover/elan) installed, run these commands from the repository directory:

```sh
lake exe cache get
lake build
```

`lean-toolchain` selects Lean, and the committed `lake-manifest.json` pins dependency revisions. Keep both files when reproducing a build; `lake update` is for intentional dependency upgrades.

[GitHub Actions](https://github.com/longdie/qfixlean/actions/workflows/lean.yml) runs `lake build --wfail` on pushes and pull requests to `main`, and supports manual runs. It downloads Mathlib's compiled cache, builds QFixLean from source, fails on build warnings (including `sorry` warnings), and checks the public import list and unchanged dependency pins. An [axiom audit](scripts/CheckAxioms.lean) checks declarations from project modules and their transitive dependencies, allowing only `propext`, `Classical.choice`, and `Quot.sound`; any other axiom makes the check fail. A [public-result check](scripts/CheckResults.lean) restates the expected algorithm outputs, probabilities, limits and construction costs with explicit allowed assumptions, then proves them through the public library. The workflow actions are pinned to commit hashes. These checks supplement review of theorem statements, assumptions, and their connection to the algorithms.

Import the public library with `import QFixLean`. After adding modules, update its generated entry point with `lake exe mk_all --lib QFixLean`. To reproduce the CI checks locally, run:

```sh
lake build --wfail
lake exe mk_all --check --lib QFixLean
lake env lean -DwarningAsError=true scripts/CheckAxioms.lean
lake env lean -DwarningAsError=true scripts/CheckResults.lean
git diff --exit-code -- lean-toolchain lakefile.toml lake-manifest.json
```

For an independent source build, start from a fresh checkout of the intended commit, keep the pinned toolchain and manifest, and download dependency caches with `lake exe cache get`. Do not copy an existing QFixLean build directory. The cache supplies compiled dependencies; QFixLean is built from its committed source. In an archive without Git metadata, compare the pinned files and source hashes against that commit instead of running the Git diff command. [Sources and licenses](SOURCES.md) record the paper versions, dependency and reference-library snapshots.

The representation uses continuous linear operators on complex inner-product spaces, with `EuclideanSpace` for finite-dimensional examples. The code provides [normalized pure states](QFixLean/Basic/State.lean) and [unitary evolution](QFixLean/Basic/Unitary.lean), including inner-product preservation, composition, and recovery by the adjoint or inverse. [Exact qubit examples](QFixLean/Examples/Qubit.lean) cover computational basis states, the superposition `(3/5, 4/5)`, and Pauli X.

The [projection interface](QFixLean/Basic/Projection.lean) covers arbitrary target subspaces, orthogonal complements, and normalized source-state projections. For orthogonal projections, [measurement weights](QFixLean/Basic/Probability.lean) sum to the input's squared norm; for normalized inputs they are probabilities in `[0,1]`. Complex inner-product bridges and global-phase invariance connect these weights to vector calculations. [Exact measurement examples](QFixLean/Examples/Measurement.lean) include a qubit with probabilities `9/25` and `16/25`, and a three-dimensional target retaining two coordinates.

The [selective phase interface](QFixLean/Basic/Phase.lean) describes target and complementary components, same-target measurement invariance, and the overlap in terms of success and failure weights. [Real-angle rotations](QFixLean/Basic/PhaseRotation.lean) use `exp (I * φ)`, with adjoint, inverse, unitarity and source-state action proofs. The [scalar phase factors](QFixLean/Basic/PhaseFactor.lean) include exact π and π/3 values and the identity `(ζ - 1)² = -ζ`. [Phase examples](QFixLean/Examples/Phase.lean) verify exact qubit outputs, probability preservation and a target with two coordinates.

The [π/3 search step](QFixLean/PiOverThree/Step.lean) constructs the unitary `U R_s U† R_P U` with both phases equal to positive π/3. For any normalized source, unitary `U`, and orthogonal target projection, its actual output has failure vector `ζ ε` times the input failure vector, failure probability `ε³`, and success probability `1 - ε³`. Here `ζ = exp (I * π/3)` and `ε` is the failure probability of `U s`. The proof includes the endpoints `ε = 0, 1` and imposes no target-rank restriction.

[Exact search-step examples](QFixLean/Examples/PiOverThree.lean) independently expand the operator product for `(3/5, 4/5)` and verify that failure probability `16/25` becomes `4096/15625 = (16/25)³`.

The [recursive construction](QFixLean/PiOverThree/Recursion.lean) keeps the source and target fixed, starting at `U₀ = U` and replacing each current unitary by its search step. Every level's actual output `Uₖ s` is normalized, with failure probability `ε₀^(3^k)` and success probability `1 - ε₀^(3^k)`. [Exact recursion examples](QFixLean/Examples/PiOverThreeRecursion.lean) check levels 0, 1 and 2, compare two single-step applications with the closed form, and include a target retaining two coordinates.

The [endpoint results](QFixLean/PiOverThree/Boundary.lean) show that initial failure zero stays zero, while initial failure one stays one; the corresponding complementary or target vector component vanishes at every level. [Monotonicity and convergence](QFixLean/PiOverThree/Convergence.lean) show that failure probabilities are nonincreasing and success probabilities are nondecreasing. If `ε₀ < 1`, equivalently if initial success is positive, failure probability and the complementary component's norm tend to zero, while success probability tends to one. This includes `ε₀ = 0` and does not assert convergence of the full state vector with its global phase. [Exact convergence examples](QFixLean/Examples/PiOverThreeConvergence.lean) cover both basis endpoints, the rational qubit state, and a three-dimensional target retaining two coordinates.

The [countable construction](QFixLean/PiOverThree/Construction.lean) records base, source-phase and target-phase primitives and their inverses. Its structural adjoint reverses products and inverts each primitive. [Resource proofs](QFixLean/PiOverThree/Resources.lean) show that its interpretation is exactly the existing recursive unitary. At level `k`, target-phase queries number `qₖ = (3^k - 1)/2`, base `U`/`U†` calls number `3^k`, and source-phase calls number `qₖ`. The same construction's failure probability is `ε₀^(2*qₖ + 1)`, and success is one minus that value. [Complete exact examples](QFixLean/Examples/PiOverThreeResources.lean) connect these costs, probabilities, normalization, monotonicity and limits, including levels 0, 1 and 2 and a three-dimensional target.

These counts describe the unoptimized recursive construction: each target phase or its inverse costs one query, base calls have no target-query cost, and the input source is supplied. Source phases are counted separately. They are not physical gate counts or bit-flip oracle query counts, and do not establish optimal implementation costs. This completes the project's π/3 core verification scope, rather than every application or physical implementation in the 2005 paper. Measurement currently covers two-outcome projection probabilities; mixed states, POVMs, and postmeasurement state updates are outside this interface.

For the 2014 scheme, the [Chebyshev ratio bounds](QFixLean/Polynomial/ChebyshevBounds.lean) and [standard parameter analysis](QFixLean/Polynomial/ChebyshevParameters.lean) prove scalar error guarantees. With positive degree `L` and `0 < δ < 1`, the parameter is `γ = 1 / cosh(arcosh(1/δ)/L)`, and the normalization denominator is exactly `T_L(1/γ) = 1/δ`. For success parameter `λ ∈ [0,1]` satisfying `λ ≥ 1 - γ²`, the signed ratio `T_L(sqrt(1-λ)/γ) / T_L(1/γ)` has absolute value at most `δ`, its square is at most `δ²`, and the complementary scalar model is at least `1 - δ²`. The guarantee holds uniformly above any matched lower bound `λ₀`; these scalar bounds do not require odd degree.

The [conditional quantum guarantee](QFixLean/FixedPoint/Conditional.lean) explicitly assumes that an actual normalized output's failure probability equals this squared ratio, with `λ` taken from the actual initial state's success probability. Under that formula premise and the promise interval, it proves failure at most `δ²` and success at least `1 - δ²` for the same output. [Exact examples](QFixLean/Examples/Chebyshev.lean) include the negative cubic ratio `-1/26` and a degree-one qubit instance whose formula premise is proved directly. This reusable conditional interface remains available. The explicit phase algorithm now discharges its formula premise through the correctness proof below; bit-oracle query costs and optimality are separate.

[Generalized phase sequences](QFixLean/FixedPoint/PhaseSequence.lean) now execute arbitrary target/source phases with a fixed reference state and explicit time order. Their original bad/good component span is invariant, including degenerate inputs. The [canonical reduction](QFixLean/FixedPoint/Reduction.lean) embeds the Euclidean bad/good coordinates isometrically onto that span when initial success lies strictly between zero and one. It intertwines every actual step and sequence with the [explicit unitary matrices](QFixLean/FixedPoint/TwoDimensional.lean); the same output's failure and success probabilities are the two coordinate moduli squared. [Convention proofs](QFixLean/FixedPoint/PhaseConventions.lean) relate P14 and P24 by parameter conversion and an exact global factor `(-1)^length`. [Endpoint proofs](QFixLean/FixedPoint/PhaseBoundary.lean) retain accumulated phases and show zero/one success stays zero/one for any sequence. [Exact examples](QFixLean/Examples/FixedPointReduction.lean) check independent operator and matrix calculations, time order, complex phases and an arbitrary-rank target. These general evolution results are used by the explicit phase correctness proof below.

The [amplitude recurrence bridge](QFixLean/FixedPoint/AmplitudeRecurrence.lean) now proves that the same actual output's failure probability equals the squared modulus of the terminal [complex polynomial](QFixLean/Polynomial/PhaseRecurrence.lean), evaluated at the initial failure magnitude. A list of ℓ generalized iterations uses `2*ℓ` recurrence angles and ends at amplitude index `2*ℓ+1`, with initial terms `1, x` and update `a_next = x*(1+exp(-iφ))*a_current - exp(-iφ)*a_previous`. The [interleaved-matrix proof](QFixLean/FixedPoint/Interleaved.lean) eliminates the auxiliary coordinate without division; exact vector identities retain the accumulated phase, and the probability theorem includes initial success zero and one. P14 execution uses the existing parameter conversion and retains its additional `(-1)^ℓ`. [Exact recurrence checks](QFixLean/Examples/FixedPointRecurrence.lean) compare direct execution with recurrence calculations, including a genuinely complex terminal amplitude. The specified scalar phase recurrence and its correspondence with the explicit algorithm are proved below.

The [quasi-Chebyshev algebra preparation](QFixLean/Polynomial/QuasiChebyshev.lean) now specializes that recurrence to `φₙ = 2*arctan(sqrt(1−γ²)*tan(nπ/L))`. Positive odd lengths avoid tangent poles; each complex denominator factor is nonzero. The numerator polynomials satisfy the exact cleared recurrence with adjacent indices `n` and `n−1`, and a complete `L−1` angle list evaluates to `N_L(x)/D_L` for any complex input. Normalization `N_n(1)=D_n` follows independently of a Chebyshev formula. [Exact checks](QFixLean/Examples/QuasiChebyshev.lean) cover signs, short prefixes, `L=1`, `γ=1`, and two independent cubic calculations at `L=3`. The terminal identity and explicit phase correspondence are proved below. The reusable conditional error theorem retains its formula premise; the new algorithm theorem proves it. The bit-oracle implementation and resource proofs are described below.

The [cyclic tangent sum](QFixLean/Polynomial/CyclicTangentSum.lean) proves that, for every subset `S` of a positive odd cycle, `∑_j ∏_{m∈S} i*tan((m+j)π/L)` equals `L` when `S.card` is even and zero otherwise. Indices are taken modulo `L`; the empty subset and `L=1` are included. An independent [root-polynomial proof](QFixLean/Polynomial/CyclicTangentProduct.lean) supplies the nonzero tangent product for the downward induction. Injective enumerations, fixed coefficients and the `sqrt(1−γ²)` scaling connect the result to the existing phase tangents, including `γ=1`. [Exact examples](QFixLean/Examples/CyclicTangent.lean) compare direct three-term arithmetic with the general theorem, exhibit a repeated-index counterexample, and check a composite cycle with only three distinct translates but all nine shifts counted. The weighted comparison, scalar identity and explicit phase integration are proved below; bit-oracle costs are proved below.

The [quasi-Chebyshev identity](QFixLean/Polynomial/QuasiChebyshevIdentity.lean) proves, for every positive odd `L` and `0 < γ ≤ 1`, that the existing numerator is `γ^L T_L(X/γ)`, its denominator is `γ^L T_L(1/γ)`, and the same `L−1` angle recurrence has terminal value `T_L(x/γ)/T_L(1/γ)` for every complex `x`. For real input this is exactly the signed M11 amplitude, with its square equal to the terminal modulus squared. The proof connects [actual finite line layouts](QFixLean/Polynomial/LineTilings.lean) to [cyclic weights](QFixLean/Polynomial/TilingWeights.lean), expands distinct endpoint subsets using M15, and counts every rotation through a permutation double sum. [Exact checks](QFixLean/Examples/QuasiChebyshevIdentity.lean) include `L=1`, `γ=1`, independent cubic calculations and the value `−1/26`; an [actual periodic length-nine tiling](QFixLean/Examples/CyclicTilings.lean) has three distinct rotations, each counted three times. This scalar identity is used in the actual algorithm correctness proof below; oracle resources are proved below.

The [explicit phases](QFixLean/FixedPoint/ExplicitPhases.lean) now connect the P14 inverse-cotangent schedule to the P24 execution: each converted target angle differs by one full turn, while the exact operators differ by the retained global factor `(-1)^ℓ`. The [correctness proof](QFixLean/FixedPoint/Correctness.lean) identifies the actual output's failure probability with `[T_L(sqrt(1−λ)/γ)/T_L(1/γ)]²`, and its success probability with one minus that value, for `L=2ℓ+1` and `0<γ≤1`. The probabilities include initial success zero and one, the empty sequence and arbitrary target rank. With the standard parameter and `λ≥1−γ²`, the same actual P14 output has failure at most `δ²` and success at least `1−δ²`, with no formula hypothesis. A matched lower bound gives a uniform guarantee using phases independent of the unknown actual λ. [Exact algorithm checks](QFixLean/Examples/FixedPointCorrectness.lean) compare direct operator calculations with the general formula, retaining complex phases and signed amplitudes. The implementation below supplies bit-flip oracle semantics, ancilla restoration, finite degree selection and query bounds.

The [Hilbert ancilla space](QFixLean/Basic/Ancilla.lean) uses the square-sum norm on two data components. The [target-controlled bit-flip oracle](QFixLean/FixedPoint/Oracle.lean) is unitary on the whole extended space. Two calls, surrounding `diag(1, exp(iφ))` on the ancilla, implement the exact data target phase and restore the ancilla to zero for every data vector. [Preparation conjugacy](QFixLean/FixedPoint/Preparation.lean) implements each fixed-source phase by `A†`, the reference-state phase, then `A`. The [countable expression](QFixLean/FixedPoint/Construction.lean) and its [unitary interpretation](QFixLean/FixedPoint/Compilation.lean) compile the same M17 phase list, preserving its order and the exact P14 factor `(-1)^ℓ`. [Oracle checks](QFixLean/Examples/Oracle.lean) include basis XOR, direct superposition calculations, repeated ancilla reuse and a rank-two target.

[Finite parameter selection](QFixLean/FixedPoint/Parameters.lean) defines `B = log(2/δ)/sqrt(λ₀)`, `ℓ = ceil(B/2)` and `L = 2ℓ+1`. It proves the matching condition `1−γ²≤λ₀` for the standard parameter, together with `Q < B+2` and `L < B+3`. The [joint algorithm theorem](QFixLean/FixedPoint/Resources.lean) assumes a normalized reference, unitary preparation, orthogonal target, `0<δ<1`, and actual prepared success at least `λ₀∈(0,1]`. Its actual compiled output is normalized with a clean ancilla, agrees with the proved explicit algorithm, and has failure at most `δ²` and success at least `1−δ²`. The same unoptimized expression uses `Q=2ℓ=L−1` bit-flip queries, `ℓ+1` calls to `A`, `ℓ` to `A†`, and `ℓ` each to reference and ancilla phases. Supplying the prepared input removes the initial extra `A`. [A joint exact example](QFixLean/Examples/FixedPointResources.lean) uses a nonidentity rational rotation, `λ₀=1/4` and `δ=1/2`: degree five, success at least `3/4`, four bit-flip queries, three `A` and two `A†` calls.

These are construction costs in an exact phase model: `A` and `A†` have no target-query cost in the stated bound, and reference and ancilla phases are separately supplied operations. M10 counts target-phase queries, whereas M18 counts bit-flip queries; their units require an implementation conversion before comparison. The finite upper bound establishes no query-optimality lower bound, minimal gate cost or running time, and exact real phases do not provide finite-precision phase synthesis. The checks above provide the project-wide proof and reproduction acceptance entry points. Course reports and presentation materials (M20) remain planned.
